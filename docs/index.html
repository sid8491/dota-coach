DOTA COACH · ARCHITECTURE

A local Dota 2 coaching assistant

Dota's Game State Integration streams JSON to a local Flask server. Each tick is summarized, diffed against the previous tick, gated through cooldowns & freshness checks, sent to a local LLM via Ollama, and spoken aloud by Piper TTS — without ever blocking the GSI POST.

01 What this project is

Dota Coach is a Windows-only Python process that listens to Dota 2's Game State Integration (GSI) on 127.0.0.1:8000, turns each game tick into a flat summary, watches for moments worth coaching (death, low HP/mana, ult ready, missing enemies, periodic check-in, …), and asks a local LLM via Ollama (or Gemini) for a one-line tactical tip. The tip is logged and read aloud through Piper TTS.

INPUT

Dota GSI

Game client POSTs JSON every ~100 ms with map, hero, items, abilities, minimap, buildings, events.

SERVER

Flask + thread

One endpoint POST /gsi/. Returns 200 immediately. LLM work runs on a daemon thread.

BRAIN

Local LLM

Ollama by default (qwen3.6:27b / gemma4:e4b). Gemini supported via OpenAI-compat endpoint.

OUTPUT

Piper voice

Synthesized to a temp WAV and played through winsound so you don't have to read mid-fight.

Dota client Flask server LLM (Ollama / Gemini) Piper TTS

03 End-to-end flow (per tick)

The pipeline is one-way per request. The Flask handler returns 200 immediately; the LLM call happens off-thread so a slow model never blocks GSI.

STAGE 01🎮

GSI POST

Dota client POSTs JSON ~10×/sec to http://127.0.0.1:8000/gsi/ with auth token.

STAGE 02🧹

Summarize

filter_minimap drops ward/creep/rune icons. summarize() flattens to a contract dict.

STAGE 03📊

Diff & emit events

EventDiffer.process compares prev↔curr, emits typed events (death, low_hp, …).

STAGE 04🧠

Gate + LLM

Coach.maybe_advise applies cooldowns + inflight guard, picks one trigger, calls LLM on a thread.

STAGE 05🔊

Filter + speak

Drop OK, stale, or duplicate tips. Survivors → log + Piper TTS.

main.gsi() in code form

data    = request.get_json(...)            # raw GSI tick
auth    = data["auth"]["token"]            # 401 on mismatch
data["minimap"] = filter_minimap(...)      # drop wards/runes/creeps
curr    = summarize(data)                  # → flat dict contract
matchid = curr["matchid"]                  # → rotate log if new match
events  = differ.process(curr)             # stateful diff
coach.maybe_advise(curr, events)           # → daemon thread for LLM
print_snapshot(curr)  # every 30s in ACTIVE_GAME_STATES
return ("ok", 200)                         # never block on LLM

06 Events & triggers

  
EventDiffer is stateful — it holds prev, debouncing buffers, an emitted-server-event dedup set capped at 500, and a slot_to_hero map it builds up over the match. It only diffs when both ticks are in ACTIVE_GAME_STATES (pre-game and post-game are intentionally inert). A change in matchid triggers _reset().

Debouncing & dedup

  
    
    
  • Status set (silenced/stunned/…): STATUS_DEBOUNCE_SEC = 2 — must be stable for 2 s before emitting status_on / status_off.
    • 
    
  • Vision set (enemy hero on minimap): VISION_DEBOUNCE_SEC = 3 — same idea for enemy_seen / enemy_lost.
    •

    • 
  


  
Slot → hero inference

  
GSI exposes player slots (0–9) but not always the hero behind them. The differ builds slot_to_hero by (a) the player's own hero, (b) observing victim/killer slots on CHAT_MESSAGE_HERO_KILL when exactly one hero of that side just vanished from the minimap, and (c) elimination once 5 enemy heroes have been seen.







  
07 The Coach pipeline

  
Coach.maybe_advise(summary, events) is the gate. It always refreshes latest_summary (used later for the freshness check), then walks a series of guards. Only one trigger fires per call, and the LLM runs on a daemon thread.


  

    
🎯pick trigger_pick_trigger — first event whose type is in TRIGGER_TYPES

    
⏱️inflight + cooldown_inflight, MIN_INTERVAL_SEC=8, PER_TRIGGER_COOLDOWN_SEC=30

    
🧠LLM call_call_llm → Ollama or Gemini, 120 s timeout, temp 0.4

    
🌡️freshnessplayer respawned? HP/MP recovered? enemies back?

    
🔁similarityJaccard ≥ 0.65 against recent_tips drops the tip

  


  
Filter funnel — what can drop a tip

  

    
events arriveFrom EventDiffer.process(curr). Empty → return early.→ pass

    
no eligible triggerNo event type in TRIGGER_TYPES, or a non-milestone level_up.silent drop

    
inflightA previous LLM call is still running — the next tick wins.silent drop

    
global cooldownLess than MIN_INTERVAL_SEC = 8 game-seconds since last call.silent drop

    
per-trigger cooldownSame trigger type fired < PER_TRIGGER_COOLDOWN_SEC = 30 ago.silent drop

    
LLM callDaemon thread; system prompt + user message; num_predict=400, temp 0.4.await

    
empty contentSome thinking models put output in thinking; logged with a thinking_excerpt.drop & log

    
tip == "OK"Model explicitly declined — logged as [coach] declined.drop & log

    
staleRe-checked vs latest_summary: respawned, HP≥FRESH_HP_RECOVERED_PCT=60%, MP≥FRESH_MP_RECOVERED_PCT=50%, or enemies_missing < FRESH_MISSING_ENEMIES_MIN=2.drop & log

    
too similarJaccard over word sets ≥ 0.65 against any of the last RECENT_TIPS_MEMORY=8 tips.drop & log

    
survivesPrint [COACH][model] tip…, append to recent_tips, scan for items → recommended_items, hand to TTS.speak.✓ shipped

  


  
Stateful coach memory

  

    
recent_tips
deque(maxlen=8). Fed back into the next prompt so the model gets a "don't repeat these" reminder.

    
recommended_items
Set, reset per match. _extract_recommended_items() scans each shipped tip against OpenDota's full item-dname list. Added to the next prompt as "items you've already recommended".

    
latest_summary
Always overwritten on every tick. Used by _stale_reason() when the LLM finally responds — so a "you're at 28% HP" tip gets dropped if you're already back to full.

  







  
08 The LLM prompt anatomy

  
Two messages: a system prompt that pins behavior, and a user message built by _build_prompt() from the summary, recent events, recent tips, and the trigger string.


  
System prompt — guardrails

  
    
    
  • Output: one actionable tip, one or two short sentences. No greeting, no padding. Reply just OK if nothing useful.
    • 
    
  • Visibility rules baked in: own hero fully visible; enemy items/HP/mana never visible; enemy positions only when in vision; ally items/HP not visible.
    • 
    
  • Only suggest abilities/items that appear in the user message — no hallucinations.
    • 
    
  • Per-trigger focus block (death → respawn decision; low_hp → escape; ult_ready → where/whom; periodic_check → next item or strategic call; …).
    • 
    
  • "Good vs Bad" few-shot examples that punish empty advice like "save it for the right moment" in favour of specific spatial / item / target calls.
    • 
  


  
User message — every block, in order

  

    
Game contextphase (PRE/EARLY/MID/MID-LATE/LATE), hero + roles + attribute, lane bucket (from _classify_lane), facet, clock, score, day/night, level, HP%/MP%, status flags, K/D/A, CS, gold, GPM

    
Your abilitiesname + dname, level, ult/passive flag, cooldown ("off cd" or "ON CD Xs"), first-sentence description from OpenDota

    
Your itemsdisplay names of equipped items (no empty slots)

    
Allies in visionhero short name + lane bucket — only those visible on the minimap

    
Enemy lineupunion of every enemy hero ever seen this match (so the model knows the full opposing lineup)

    
Visible enemiesN/5 currently visible + N missing + per-hero lane bucket

    
Recent eventslast 8 typed events (e.g. level_up: Leveled to 6)

    
Recent tipslast 8 tips already given this match — "DO NOT repeat or rephrase, give a DIFFERENT angle"

    
Already-recommended itemsevery item dname this match's prior tips named — model must pick something else next

    
Trigger"type: msg" e.g. periodic_check: periodic check-in

    
Trigger tailperiodic_check gets an extra "(a) build [item] next, or (b) push/smoke/defend [lane]" framing tail

09 TTS pipeline

  
Piper synthesizes to a temp WAV, winsound.PlaySound plays it, then the WAV is deleted. A single _lock serializes playback so tips don't talk over each other. Each speak() call spawns its own daemon thread, so the coach pipeline is never blocked by audio.


  

    
DEFAULT
en_US-amy-medium
ONNX + JSON sidecar under models/. Override with $env:PIPER_MODEL.

    
FALLBACK
Missing voice
No exception — prints [tts] model not found and silently disables speech. Tips still log.

    
KILL SWITCH
TTS_DISABLED=1
Set the env var to mute the run entirely. Useful for development.

  







  
10 Logging behavior

  
setup_logging() must run before importing coach — otherwise coach's module-level prints don't get captured. main.py respects that import order.

  
    
    
  • Logs go under logs/ (auto-created).
    • 
    
  • Pre-match output writes to logs/session_<timestamp>.log.
    • 
    
  • On the first tick that exposes a matchid, switch_to_match() renames the session log to <matchid>.log — carrying pre-game content forward only from a session_* log, never from a previous match's log.
    • 
    
  • Both stdout and stderr are tee'd via the _Tee class → console + file.
    • 
    
  • Werkzeug's per-request access logger is set to WARNING in the same function, to silence the 200 - spam.

14 Extending the coach


  

    Add a new trigger type
    
    
      
  1. Decide where to detect it. Diff-based? Add to a _diff_* method on EventDiffer. Server-event? Add a branch in _parse_server_event. Derived? Extend _derived_triggers.
    2. 
      
  2. Emit it with self._ev(clk, "your_type", "human-readable msg", ...extra).
    3. 
      
  3. Add "your_type" to coach.TRIGGER_TYPES so the gate considers it.
    4. 
      
  4. Add a one-line bullet to SYSTEM_PROMPT's "Trigger-type focus" section telling the model what to do for it.
    5. 
      
  5. If it can be "stale" by the time the LLM responds, extend _stale_reason().
    6.

    2.

    3. 
      
  3. Read it in EventDiffer if it produces events.
    4.
